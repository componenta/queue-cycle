# Componenta Queue — PostgreSQL / Cycle Database

Постоянная очередь для [Componenta Queue](https://github.com/componenta/queue).
Пакет использует Cycle Database напрямую и не зависит от Componenta App или CQRS.
[Полная документация](README.md) содержит примеры настройки и все ограничения.

## Возможности

- Публикация с заданным идентификатором и отложенной доступностью.
- Короткие транзакции выбора и подтверждения; обработчик выполняется вне них.
- Аренда доставки с отдельным случайным токеном и проверкой актуального времени
  базы после получения блокировки.
- Восстановление после падения процесса, ограничение числа выдач и отложенные повторы.
- Сохранение исходных байтов ошибочного сообщения, ограниченная пагинация,
  идемпотентные повторный запуск и окончательный отказ.
- Явная публикация в существующей бизнес-транзакции через
  `TransactionalPublisher::stage()` без её самостоятельного подтверждения.
- Ограниченная очистка завершённых записей и разрешённой истории ошибок.

Требуются PHP `^8.5.13` на 64-битной платформе, `pdo_pgsql`,
`cycle/database:^2.24`, `componenta/queue:^1.0` и PostgreSQL 16+ с UTF-8.
Оператор приложения явно создаёт отдельную схему и вызывает `Schema::install()`
при установке. Создание объектов очереди не выполняет SQL и не меняет схему.
Допустимые имена схем сохраняются точно, включая двойные кавычки и точки с
запятой. Установка выполняется одной транзакцией. Подтверждённый откат удаляет
созданные этой транзакцией объекты и сохраняет существующие.
При `IndeterminateOperationException` перед повтором нужно проверить фактическое
состояние базы.

## Владение и восстановление

Все значимые операции обращаются к write-соединению. Обычные операции требуют
отсутствия чужой открытой транзакции; для атомарности с бизнес-изменением
используется отдельный метод `stage()` на том же физическом соединении.

В собственных транзакциях адаптер локально выбирает `DateStyle = 'ISO, YMD'`,
чтобы даты PostgreSQL читались однозначно и сохраняли микросекунды. После commit
или rollback возвращается исходная настройка сессии. `stage()` не меняет DateStyle
вызывающей бизнес-транзакции.

Подтвердить доставку может только владелец действующего токена. Истёкшая аренда
не продлевается, даже если другой процесс ещё не получил сообщение. Закрытие
receiver лишает его локальных прав, оставляет работу для восстановления по
истечении аренды и не отключает переданное приложением соединение.

Объекты receiver и delivery нельзя клонировать: они владеют состоянием сессии
или резервирования, которое должно оставаться согласованным с завершением
обработки. Для независимой сессии получите новый receiver у очереди. Неизменяемые
сообщения и снимки метаданных остаются обычными значениями.

При потере ответа на COMMIT результат считается неопределённым. Код не делает
противоположную операцию и не предполагает откат. Неопределённую публикацию
можно повторить с теми же ID, байтами, заголовками и исходной задержкой, пока
хранится её запись дедупликации. Внешние эффекты обработчика требуют прикладной
идемпотентности: повторная доставка возможна.

## Проверки

Для проверки с рабочей копией ядра:

```sh
php tools/development.php ../componenta-queue
COMPOSER=composer.dev.json composer update
export QUEUE_TEST_DSN='pgsql:host=127.0.0.1;port=5432;dbname=queue_tests;connect_timeout=2'
export QUEUE_TEST_USER=queue_test
COMPOSER=composer.dev.json composer check
```

Тесты используют случайные схемы в явно выбранной тестовой базе, отдельные
соединения и процессы, реальные блокировки, падение worker и потерю ответа на
COMMIT. Общий контракт адаптеров загружается из установленного ядра.
Результаты и границы проверок описаны в [отчёте](docs/verification.md).

Сценарий `benchmarks/QueueWorkload.php` измеряет реальные операции PostgreSQL,
включая работу с отложенным backlog. Он требует отдельный `QUEUE_BENCH_DSN`;
результаты одного процесса на общей машине не являются обещанием пропускной
способности промышленной установки.
